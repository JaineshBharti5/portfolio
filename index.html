Package Abandonment Predictor

Complete · GitHub
91%

Accuracy in predicting which widely used npm packages will become unmaintained, an early warning for software supply-chain risk. Recall on the unmaintained class is also 91%, at 76% precision.

Approach

I collected metadata for 1,758 npm packages from the npm registry and GitHub, then used PySpark to engineer features and label 1,632 of them as maintained or unmaintained. A Random Forest classifier is trained on those features, and a second run without the strongest one, publish recency, shows how much the model leans on it. A Streamlit dashboard turns the output into searchable risk scores and highlights high-risk packages that are still maintained.

Dataset
1,632

npm packages collected from the npm registry and GitHub: 388 unmaintained and 1,244 maintained. In an ablation test, dropping the strongest feature brings accuracy down to 86%.

  • 1,758 packages collected, 1,632 labeled
  • Publish recency carries about half of the feature importance
  • Without it, recall on unmaintained drops to 64%

Drift

A drift detection tool that analyzes streaming data and flags when it starts to shift, working across multiple data formats.

Approach

The tool takes data in different formats, processes it as a stream and watches how its distribution changes compared with earlier data. When incoming data starts drifting away from what a model was built on, it gets flagged early, before the model quietly gets worse.

AP-HRRN CPU Scheduler

CompleteGitHub
(W+S)÷S

The HRRN response ratio is the baseline. AP-HRRN adds aging, a preemptive response ratio and exponential-averaging burst estimation to fix the weak spots of SJF and HRRN, and ships with a simulator.

Approach

The starting point is HRRN's response ratio, (W+S)/S, with three fixes added on top: aging so long-waiting processes don't starve, a preemptive response ratio, and exponential averaging to estimate burst times. A Python simulator then runs AP-HRRN, SJF and HRRN on the same workloads so the results can be compared fairly.

Comparison
3

algorithms (AP-HRRN, SJF and HRRN) compared in a single Python simulator, built for the Operating Systems course.

  • Aging so long-waiting processes do not starve
  • Preemptive response ratio
  • Exponential-averaging burst estimation
  • Backed by 18 automated tests
